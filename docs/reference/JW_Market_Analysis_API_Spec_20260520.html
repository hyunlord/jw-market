PAGE 3 심층분석

  1. 최초 brand 진입 시: GET /api/deep-analysis/{brand} — forecast + simulation + events + ai_analysis (4단). query 없이 단일 호출로 6 source/measure 조합 × 최대 기간 (history 5년 + forecast 10년) 모두 응답 — 사용자 토글에 따라 클라이언트가 slice

B — Simulation (단일 brand 시나리오 예측 + Anomaly 감지)

응답 키: data.simulation.by_combo[combo_key]
의미: 사용자가 단일 brand 를 선택하면 (1) 실적 시계열 (2) 3 시나리오 (base/upper/lower = 모델 point estimate + CI 상·하한) (3) 신뢰도·시장 대비·Momentum (4) Anomaly 감지 + 이슈 매칭 결과를 제공. 가용 6 brand (target + Top 5) × 6 combo 모두 포함.
모델 정책 (data-size dispatch): brand 의 history 데이터 양에 따라 backend 가 자동으로 적절한 모델 선택. UBIST 60+ → Prophet basic + event proxy 1~2 / 40~59 → SARIMAX + event 1~2 / 30~39 → SARIMAX base / 20~29 → Holt-Winters / 12~19 → Linear / <12 → Mean·median. IQVIA 20+ → Holt-Winters or damped ETS / 12~19 → Linear / <12 → Mean. 현재 데이터 한계: UBIST 최대 64개월, IQVIA 최대 22분기 → Prophet+event_5 (100+ 포인트 요건) 불가, IQVIA 의 SARIMAX 도 무리. 실제 brand 데이터 양 기준 자동 fallback.
시나리오 정의 (옵션 B 동화): scenarios.base = 선택 모델의 point estimate. scenarios.upper/lower = 같은 모델의 CI 상·하한 (horizon 차등 적용 — 1년=95%, 3년=90%, 5년=80%, 10년=50%). 차트의 음영 = 시나리오 선과 동일 좌표. anomaly mean shock 방식 (직전 cycle 의 방식 B 추천) 은 stress 필드에 별도 보관 — 사용자 화면에서 primary 로 표시 X.
Anomaly 감지: 과거 history 의 rolling z-score (window 6m / 4q) 기반. 임계 |z| ≥ 3.0 또는 severe YoY |YoY| ≥ 50% 통과 시 표시. 통과 sample 부족 시 top-N=3 fallback (가장 큰 |z| 3건). 좌측 events 와 시점 매칭 → matched_event_id 노출.
주의 - 이벤트 반영 한계: 정식 labeled events table 부재 (raw 데이터에 가격변동·시장신규진입 proxy 만 존재). 따라서 base/CI 산정에 들어가는 event regressor 는 proxy_light 모드만 가능. PPTX 의 "이슈 영향이 직접 예측에 반영" 의도는 부분 구현 (proxy 한정). warnings 필드로 노출.
frontend: brand select dropdown (선택 brand + 상위 5). 차트 = history 실선 + 시나리오 3 선 + CI band 음영 (시나리오와 일치). KPI 카드 6장 (시나리오 3 + 신뢰도 + 시장 대비 + Momentum) + 하단 anomaly 박스.
