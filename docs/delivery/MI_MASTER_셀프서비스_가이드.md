# MI Master 셀프서비스 가이드

작성 기준: 2026-07-26 정본 workbook과 자동 discovery 코드
대상: MI팀 실무자, 시장분석 운영 담당자

## 1. 이 문서로 할 수 있는 일

MI Master는 JW 전략 시장의 기준 파일이다. 이 가이드대로 하면 다음 작업을
코드 수정 없이 준비할 수 있다.

- 기존 시장의 class, molecule, 제형 등 매핑값 수정
- 기존 시장에 브랜드·제품 추가
- 표준 형식의 새 전략 시장 추가
- 시장 제거

다만 파일을 고치는 것과 운영 화면에 반영하는 것은 별도 단계다. 파일 변경 후
검증, catalog 재생성, mart 검증, test2·운영 승격은 승인된 운영 절차를 따라야 한다.

> **절대 구분**
>
> MI Master는 Market Landscape와 Competitive Dynamics라는 **두 전략뷰**의
> 기준이다. 일반뷰는 ATC4 코드만으로 시장을 정하므로 이 파일에서 일반뷰 정의를
> 바꾸지 않는다.

## 2. 파일과 시트 구조

현재 정본 파일은 저장소의 다음 위치에 있다.

```text
data/JW 주요 약품 수동 매핑/
  MI팀_시장분석 AI_시장 분석 Master Version
  (원본파일 점검용 재공유 2026.05.18).xlsx
```

파일명은 시스템이 정본 1개를 식별하는 계약에 포함된다. 새 버전을 반영할 때는
별도 사본에서 먼저 작업하고, 승인 후 정본 경로와 source pin을 함께 갱신해야 한다.
개인 PC의 임의 폴더에 둔 파일은 운영 입력이 아니다.

### 2.1 공통 시트 3개

| 시트 | 역할 | 실무자가 주로 하는 일 |
| --- | --- | --- |
| `JW 전체_JWP MKT 구분` | 전체 제품·시장 구분 참고 | 기존 분류 확인 |
| `시장정의 & Target` | 제품별 시장 범위, 분석 축, 직접 경쟁, 고객 우선순위 | 시장 추가·변경 시 반드시 수정 |

## 3. `시장정의 & Target` 작성법

시장 하나가 여러 대상 제품을 가지면 제품별 열이 여러 개일 수 있다. 프로그램은
6행 제품명을 상세 시트 이름과 매칭해 같은 전략 시장으로 묶는다.

| 행 | 항목 | 의미 | 필수 여부 |
| ---: | --- | --- | --- |
| 5 | 구분/JWP MKT | 담당·업무 구분 | 업무상 필요 |
| 6 | PRODUCT NAME KOR | 대상 제품명. 상세 시트 이름과 매칭 기준 | **필수** |
| 7 | ATC 4 CODE | 시장 후보 ATC4 | **필수** |
| 8 | ATC 4 DESC | ATC 설명 | 권장 |
| 9 | NHI TYPE | 급여 분석 기준 | 해당 시장만 |
| 10 | 분석 데이터 출처 | `UBIST`, `IQVIA`, 또는 둘 다 | **필수** |
| 11 | 분석값 | 매출·처방량 등 분석 값 설명 | 권장 |
| 14 | Class | Class 축 사용 여부·정의 | 해당 시 |
| 15 | Molecule | 성분 축 사용 여부·정의 | 해당 시 |
| 16 | Brand | 브랜드 축 | 해당 시 |
| 17 | Dosage Form | 제형·투여경로 축 | 해당 시 |
| 18 | Strength | 용량·pack 축 | 해당 시 |
| 19 | 기타 | OX/GX, biosimilar, 기타 축 | 해당 시 |
| 22~44 | 전체 치료 시장 정의 | Market Landscape의 추가 범위 | 해당 시 |
| 48~50 | 브랜드 직접 경쟁시장 정의 | Competitive Dynamics를 좁히는 기준 | 해당 시 |
| 54~57 | Target Customer Priority | 고객 우선순위 | 해당 시 |
| 61~64 | 분석 지표 | 시장별 표시 지표 메모 | 해당 시 |

값이 없다는 의미와 “미정”은 다르다. 필수값이 비어 있으면 시트를 발견하지 못하거나,
원천 종류를 판정하지 못해 검증 단계에서 실패한다.

## 4. 상세 시트 작성법

상세 시트의 표 헤더는 **3~12행 사이**에 있어야 한다. 헤더에는 다음 두 종류가
반드시 포함돼야 한다.

1. ATC를 식별할 수 있는 열
2. MOLECULE/성분 또는 PRODUCT/제품을 식별할 수 있는 열

상세 시트마다 원천 컬럼명이 조금 다르므로 기존 같은 원천 시트를 복사하는 것이
가장 안전하다.

아래 표는 실무자가 다루는 공통 의미를 설명한다. 원천별 실제 헤더명과 연결 관계의
전수 정본은 [MI Master 컬럼 매핑 카탈로그](../../pipeline/etl/config/master_column_mapping_catalog.md)에
있다. 이 표에 없는 원천 전용 열도 임의로 이름을 바꾸거나 삭제하지 않는다.

| 컬럼 종류 | 뜻 | 처리 원칙 |
| --- | --- | --- |
| ATC4 | 시장 후보 범위 | 일반뷰 정의가 아니라 전략 시트의 후보 범위 |
| 제품·브랜드 | 실제 시장 구성원 | 원천 제품명과 매칭 가능해야 함 |
| molecule/성분 | 성분 표시·매칭 | recode 값이 있으면 정책에 따라 반영 |
| class | 시장 내 분류 | 기존 원천을 지우지 않고 분류를 추가하는 축 |
| dosage form/제형 | 제형·투여경로 | 제품 단위로 적용 |
| strength/pack | 용량·포장 | 제품 단위로 적용 |
| NHI/급여 | 급여 구분 | 시장별 사용 여부가 다름 |
| manufacturer/company | 제조·판매사 | 원천별 명칭 차이를 표준화 |
| recode 열 | 화면·분석용 표준값 | 아래 recode 정책 적용 |
| 제외 마커 | 해당 행 또는 class 제외 | **셀에 `제외`를 명시**. `비제외`는 제외로 보지 않음 |

### 4.1 recode 정책

| 정책 | 대상 예 | 동작 |
| --- | --- | --- |
| OVERWRITE | molecule, dosage form, NHI, manufacturer | canonical 값이 있으면 원천값을 교체 |
| ADD_ONLY | class 같은 분류 축 | 원천 구성원을 삭제하지 않고 분류를 추가 |

`Class Recode`와 원래 성분명은 같은 개념이 아닐 수 있다. 제이클처럼 class는
`Trisulfate`지만 표시 성분은 원천 `MOLECULE DESC`를 유지하는 예외가 있다.

### 4.2 `cd_filter`의 의미

Competitive Dynamics는 Market Landscape 전체에서 직접 경쟁 범위만 남긴다.
48~50행과 상세 시트의 recode·제외·필터가 그 범위를 만든다.

- 단순 시장: 상세 시트 전체를 CD로 사용
- 좁은 시장: molecule, class, 제형 등의 조건을 사용
- 여러 제품 열을 하나로 합쳐야 하는 시장: 선언 규칙 검토 필요

새로운 비교 연산이나 복합 필터가 필요하면 MI Master만으로 끝나지 않는다.
개발자 확인과 계약 테스트가 필요하다.

## 5. 시나리오별 실행 가이드

### 시나리오 A. 기존 시장의 값을 고치고 싶을 때

예: 어떤 브랜드의 class를 바꾸고 싶다.

1. 정본 파일의 사본을 만든다.
2. 해당 전략 시장의 상세 시트를 연다.
3. 제품명·브랜드명·ATC4로 대상 행을 찾는다.
4. 원천값은 보존하고 해당 recode 열의 값을 수정한다.
5. 같은 브랜드의 다른 제품 행도 있는지 필터로 확인한다.
6. `시장정의 & Target` 14~19행에서 해당 분석 축이 켜져 있는지 확인한다.
7. 변경 전·후 셀과 변경 사유를 기록한다.
8. 아래 “반영 요청 묶음”으로 제출한다.

**판정:** 기존 컬럼의 recode 값 수정은 코드 수정 없이 준비할 수 있다. 다만 시장
구성원 수나 화면 축이 바뀌면 개발자 검증이 필요하다.

### 시나리오 B. 기존 시장에 브랜드를 추가하고 싶을 때

1. 추가할 브랜드가 어느 상세 시트 시장에 속하는지 확인한다.
2. 같은 원천과 제품 유형의 기존 행을 복사한다.
3. 제품명, 브랜드명, ATC4, molecule, class, 제형, 용량, 회사 정보를 실제
   원천과 일치하게 채운다.
4. 필요 없는 recode 값은 복사된 상태로 두지 말고 지운다.
5. 제외 셀에 실수로 `제외`가 남지 않았는지 확인한다.
6. 대상 제품 자체가 새 JW 제품이면 `시장정의 & Target` 6~10행에도 열을
   추가해야 하는지 확인한다.
7. 기존 시장 구성원과 중복되지 않는지 확인한다.

**판정:** 기존 시장의 표준 행 추가는 코드 수정 없이 준비할 수 있다. 브랜드 별칭,
영문 molecule과 한글 브랜드 연결이 새로 필요하면 개발자 확인이 필요하다.

### 시나리오 C. 새 시장을 통째로 추가하고 싶을 때

1. 원천이 같은 기존 상세 시트를 복사한다.
2. 복사 시트의 이름을 새 시장명으로 바꾼다.
3. 시트의 제목, 헤더, 데이터 행을 새 시장 내용으로 교체한다.
4. 헤더가 3~12행 사이에 있고 ATC 열과 성분/제품 열이 있는지 확인한다.
5. `시장정의 & Target`의 마지막 사용 열 오른쪽에 새 열을 추가한다.
6. 6행 제품명, 7행 ATC4, 10행 원천을 반드시 입력한다.
7. 14~19행에서 사용할 분석 축을 표시한다.
8. 필요하면 22~44행 전체시장 정의, 48~50행 직접 경쟁 정의,
   54~57행 고객 우선순위를 입력한다.
9. 제품명과 상세 시트명이 서로 식별 가능하도록 이름을 맞춘다.
10. 새 시트만 있고 `시장정의 & Target` 열이 없거나, 반대 상황이 아닌지 확인한다.

저장 후 catalog 실행 시 내부 전략·ML·CD·필터 식별자, 시장 목록, 분석 축,
API 브랜드 메타데이터가 자동 생성된다. 내부 식별자는 입력하거나 화면에 노출하는
값이 아니다.

**판정:** “상세 시트 전체가 CD 시장”인 표준 신규 시장은 코드 수정 없이 발견된다.
특수 CD 필터, 기존 ID 순서 고정, 여러 제품 열 합치기가 필요하면 개발자 확인이
필수다.

### 시나리오 D. 특정 브랜드만 예외 규칙을 주고 싶을 때

MI Master 셀만으로 표현할 수 없는 예외는 선언 파일에 기록한다.

```text
pipeline/etl/config/mi_master_rules.yaml
```

지원 동작:

- `set`: 정해진 값을 넣는다.
- `copy`: 원천 필드 또는 현재 레코드의 값을 복사한다.
- `first_present`: 후보 중 첫 번째 유효값을 사용한다.
- `null_if_equal`: 두 축이 같은 값을 중복 노출하지 않게 하나를 비운다.

각 규칙에는 고유 ID, 적용 단계, 대상 조건, 동작, 업무 근거가 필요하다.

**판정:** 선언 형식으로 표현할 수 있지만 YAML과 회귀 테스트를 함께 바꿔야 하므로
개발자 작업이다. MI팀은 대상, 기대 결과, 근거를 제공한다.

### 시나리오 E. 시장을 없애고 싶을 때

1. 삭제 대신 먼저 “비활성 후보”로 기록하고 영향 화면을 확인한다.
2. 해당 상세 시트를 제거할지 결정한다.
3. `시장정의 & Target`에서 그 시트에 연결된 제품 열을 모두 제거한다.
4. 선언 파일에 해당 시트의 순서·합치기·별칭·예외가 남아 있는지 확인한다.
5. 과거 골든, catalog, mart, 화면 메뉴가 참조하는지 검증한다.

**판정:** workbook에서 삭제하면 자동 discovery 대상에서는 빠질 수 있다. 하지만
내부 순서와 과거 참조가 바뀔 수 있으므로 **시장 삭제는 반드시 개발자 확인이
필요**하다.

## 6. 수정 후 반영 절차

### 6.1 반영 요청 묶음

다음 네 가지를 함께 전달한다.

1. 수정한 workbook 사본
2. 변경한 시트·셀 목록
3. 변경 사유와 기대 화면
4. 되돌릴 때 사용할 이전 정본 파일

승인된 파일은 저장소 정본 경로에 반영하고 SHA256 source pin을 갱신한다. 운영
포털에 파일만 올리는 것과 저장소 정본을 바꾸는 것은 동일하지 않다. 어떤 경로를
사용할지는 현재 운영 절차 담당자가 결정한다.

### 6.2 자동으로 일어나는 것

정본으로 채택되고 catalog 체인이 실행되면 다음이 자동 처리된다.

1. 상세 시트 발견
2. 시장·대상 제품 열 매칭
3. Market Landscape와 Competitive Dynamics 구성
4. 분석 축과 ATC4 추출
5. recode·제외·선언 규칙 적용
6. catalog와 전략 mart 생성
7. API가 읽는 시장·브랜드 메타데이터 갱신

### 6.3 사람이 해야 하는 것

1. workbook 변경 검토와 승인
2. G3 workbook 검증
3. 신규·변경 시장의 구성원 before/after 확인
4. test2 API·화면 확인
5. 운영 승격 승인
6. 실패 시 이전 정본과 이전 mart 세대로 복원

### 6.4 반영 시간

MI Master 자체의 운영 반영 소요시간을 확정할 최신 전구간 실측은 이 저장소에서
확인되지 않았다. **[확인 필요: 정본 승인부터 운영 화면 반영까지의 SLA]**

따라서 “몇 분 뒤 자동 반영”을 전제로 업무를 진행하지 않는다. 상태가 완료되고
아래 확인 항목이 통과한 뒤 반영된 것으로 판단한다.

### 6.5 화면 확인

1. Market Landscape에서 새 시장 또는 변경 시장을 선택한다.
2. 시장 크기와 브랜드 목록이 예상 범위인지 확인한다.
3. class, molecule, 제형 등 변경 축을 선택해 값이 표시되는지 확인한다.
4. Competitive Dynamics로 이동해 직접 경쟁 범위가 더 좁아졌는지 확인한다.
5. 선택 브랜드 + 경쟁 5개가 유지되는지 확인한다.
6. 일반뷰의 같은 ATC4 결과가 의도치 않게 바뀌지 않았는지 확인한다.

## 7. 하면 안 되는 것

- 정본에서 바로 편집해 이전 버전을 잃지 않는다.
- 시트 이름만 바꾸고 `시장정의 & Target` 제품명을 그대로 두지 않는다.
- 6행 제품명, 7행 ATC4, 10행 원천을 비우지 않는다.
- 상세 시트 헤더를 3~12행 밖으로 옮기지 않는다.
- 원천값과 recode 값을 같은 열에 덮어써 근거를 없애지 않는다.
- 단순 메모에 `제외`라고 써서 행 전체를 의도치 않게 제외하지 않는다.
- 새 예외를 Python `if` 문으로 직접 추가하지 않는다.
- 일반뷰 정의를 MI Master에서 바꾸려 하지 않는다.
- test2 검증 없이 운영 반영을 확정하지 않는다.

잘못됐을 때 나타나는 대표 증상:

| 증상 | 먼저 볼 것 |
| --- | --- |
| 새 시장이 목록에 없음 | 시트 헤더 위치, 6행 제품명과 시트명 매칭 |
| 검증 단계 실패 | 필수값, 원천 표기, 상세 시트 존재 여부 |
| 브랜드가 비어 있음 | 제품/브랜드명, 제외 마커, 원천 매칭 |
| class·성분이 이상함 | recode 열, 선언 override, 중복 축 제거 규칙 |
| CD가 ML과 똑같음 | 48~50행과 특수 CD 필터 필요 여부 |
| 기존 시장 순서가 바뀜 | 시트 순서와 `strategy_order` 검토 |

되돌릴 때는 이전 정본 workbook과 source pin을 복원하고, 이전 검증 mart 세대로
복구한다. 현재 파일의 셀만 역수정하는 방식은 누락 위험이 있어 권장하지 않는다.

## 8. 자주 묻는 질문

### Q1. 제이클의 `Trisulfate`는 왜 성분에 그대로 나오지 않나요?

`Trisulfate`는 class 분류이고 표시 성분은 원천 `MOLECULE DESC`를 사용한다.
같은 값이 class와 molecule에 중복되면 molecule 축의 중복값을 비우는 선언 규칙이
있다. 이 동작은 회귀 테스트로 고정돼 있다.

### Q2. 가드렛의 TIRZEPATIDE는 왜 GLP-1RA인가요?

MI Master 업무 결정에 따라 가드렛 시장의 TIRZEPATIDE를 GLP-1RA class로
재분류하는 선언 규칙이 있다. 영문 molecule placeholder가 한글 브랜드
`마운자로`를 대체하지 않도록 별도 테스트도 있다.

### Q3. `위너프에이플러스`와 `위너프에이플러스페리`는 같은 이름인가요?

아니다. 별도 제품을 문자열 유사성만으로 합치면 안 된다. 현재 선언에는
`위너프A+` 표시를 `위너프에이플러스`로 바꾸는 규칙이 있지만,
`위너프에이플러스페리`와의 관계는 원천·MI Master 실측으로 별도 판정해야 한다.
라벨이 다르면 임의 alias를 만들지 말고 MI팀과 원천 담당자가 확인한다.

### Q4. 악템라의 Class 1/2 구조는 왜 일반 시장과 다르게 보이나요?

악템라는 MI Master의 전략 분류와 분석축 예외를 사용한다. 현재 선언은 NHI 축을
비활성화한다. Class 1/2 변경은 전략뷰 정의 변경이며, 일반뷰 ATC4 범위를 바꾸는
작업이 아니다.

### Q5. 시트 하나를 추가하면 정말 코드 수정이 없나요?

표준 시트 구조, 단순 CD 전체시장, 기존 분석 연산만 사용하는 경우에는 자동
discovery 계약으로 가능하다. 새 필터 연산, 특수 합치기, 별칭, 과거 순서 보존이
필요하면 선언 또는 코드와 테스트가 추가된다.

### Q6. 내부 번호를 직접 정해야 하나요?

아니다. 시트 순서와 제품 열에서 내부 식별자가 자동 생성된다. 내부 식별자는
사용자 입력·외부 응답으로 노출하지 않는다. 시트 순서를 함부로 바꾸면 과거 참조가
달라질 수 있으므로 순서 변경은 개발자와 협의한다.
