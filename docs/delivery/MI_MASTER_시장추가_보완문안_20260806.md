# 개발가이드 02 MI Master 시장정의 보완 문안

이 문서는 개발가이드 02의 원본 문서를 직접 수정하지 않고, 다음 개정 때
반영할 문안만 정리한 것이다. 일반뷰는 ATC4 코드 기준만 사용하며,
`market_landscape`와 `competitive_dynamics`의 전략뷰 정의와 혼동하지 않는다.

## 새 ML 시장 추가 절대 규칙

새 ML 시장은 상세 시트 순서와 `시장정의 & Target`의 target 열 순서에서
맨 뒤에만 추가한다. 중간 삽입은 기존 `ml_id`와 `cd_id`를 이동시켜
`_CD_BUSINESS_SPECS`가 다른 시장에 결속되게 한다.

2026-08-06 격리 workbook 실측에서 맨 뒤 추가는 `ml_id`와 `cd_id` 이동이
각각 0건이었지만, 중간 삽입은 ML 12건, CD 14건이 이동했고 spec identity
불일치가 11건 발생했다. 중간 삽입이 불가피하면 ID 재매핑 전용 회차가
먼저 완료되어야 한다.

## §2.10 변경 유형별 실제 수정 예시 추가 행

| 요청 | 수정 위치 | 반드시 확인 |
| --- | --- | --- |
| 새 ML 시장 추가 | 상세 시트 + `시장정의 & Target` 6/7/10/14~19/48~50/54~57행 | 맨 뒤 추가 여부, `_CD_BUSINESS_SPECS` 등록, ID drift 0, spec identity, mart 재계산, 대시보드 축 |

새 CD는 `competitive_dynamics_id`, parent `strategic_market_id`, `column_ids`,
`product_name_kor`, `filter_kind`를 `_CD_BUSINESS_SPECS`에 명시한다. 등록이
없거나 identity가 registry와 다르면 catalog 생성은 `ValueError`로 종료한다.

## §2.11 검증 체크리스트 건수 문안 대체

`ML 16 / CD 19` 같은 고정 건수를 사용하지 않는다. 변경 전 canonical
catalog의 실제 ML/CD ID 집합을 기준으로 삼고, 새 시장 추가 후 각 건수가
정확히 1 증가했는지 확인한다. 기존 identity별 `ml_id`와 `cd_id`는 모두
불변이어야 하며, 한 건이라도 이동하면 반영하지 않는다.

추가 전용 게이트는 다음 항목을 모두 통과해야 한다.

- ML/CD catalog 건수 각각 +1
- 기존 `ml_id`/`cd_id` drift 0
- 새 CD의 명시 spec과 전체 CD spec identity 결속
- CD 행 집합이 parent ML 행 집합과 같거나 진부분집합
- API registry에서 새 CD 노출
- 대시보드 bundle에서 새 ML/CD marker 검출

## §2.9 뒤에 추가할 mart → 대시보드 절차

이미지 교체만으로 새 시장 데이터가 화면에 생기지 않는다. catalog/API
registry 검증 후 다음 순서를 하나의 승인된 작업으로 실행한다.

1. `mart_build`로 일반뷰와 전략뷰 mart를 생성한다. 일반뷰는 ATC4 코드
   기준만 유지하고, `market_landscape`는 MI Master 시트 정의,
   `competitive_dynamics`는 parent 시장에서 `cd_filter`로 좁힌다.
2. sigma 검증과 post-gate를 통과한 결과만 `mart_publish`한다.
3. publish 후 `cache_brands`와 `cache_market_status`를 refresh한다.
   제거 예정인 `cache_cause`와 `cache_deep_analysis`는 신규 절차에 넣지 않는다.
4. Agent 3 브랜드 강점과 Agent 2 분석 결과가 새 시장 ID를 인식하는지
   확인한다.
5. 대시보드 API와 화면에서 새 시장, 분석 축, 브랜드 행을 확인한다.

2026-08-06 실측에서 `mart_build`는 319 ATC4 × 61개월 처리에 5시간 28분
44초가 걸렸고, 전체 시간의 61.4%가 쓰기였다. 새 시장 반영은 짧은 catalog
변경으로 끝나는 작업이 아니므로 승인 창, 디스크 여유, active ingest 0,
롤백 앵커를 먼저 확보한다.

## 대시보드 빈 차트 방지 문안

새 시장이 API registry에 나타나는 것만으로 대시보드가 완성된 것은 아니다.
화면은 `analysis_levels.data.Class`를 읽으므로 새 시장에서 선언한 축의 실제
데이터가 전부 비면 흰 화면 대신 빈 차트가 표시될 수 있다. 배포 전 각 축의
비어 있지 않은 segment를 확인한다.

악템라(`ml_011`)의 `Class 1`/`Class 2` 계약은 유지한다. 시각화는
`Class 2`를 사용하며, split-class payload는 빌더에서 `Class 1`을 보존한
상태로 generic `Class` alias를 native emit한다.
